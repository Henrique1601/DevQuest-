# 🧩 Desafios de Preenchimento de Lacunas (Code Cloze)

> [!abstract] Aprendizado Ativo & Redução de Atrito Cognitivo
> O módulo **Preencher Lacunas (Code Blanks)** introduz uma mecânica pedagógica baseada em testes *Cloze* (eliminação seletiva de termos-chave em trechos de código reais). O estudante pode resolver os desafios digitando a sintaxe diretamente ou selecionando alternativas via chips de múltipla escolha.

---

## 🎯 1. Princípios Pedagógicos

Construir algoritmos do zero em uma folha em branco pode gerar sobrecarga cognitiva (*blank canvas syndrome*) para quem está aprendendo uma nova biblioteca ou método.
O formato de preenchimento de lacunas ataca diretamente este gargalo:
* **Foco no Conceito Crítico**: Isola a tomada de decisão (ex: quando usar `.map()` vs `.filter()`, ou onde colocar dependências em `useEffect`).
* **Memória Muscular & Sintaxe**: No **Modo Digitação**, o aluno digita a palavra exata (`reduce`, `await`, `ON`), reforçando os caminhos neurais de escrita de código.
* **Acessibilidade Mobile & Rápida**: No **Modo Múltipla Escolha**, o aluno interage rapidamente por toques na tela do celular com chips animados, tornando os estudos viáveis em pausas curtas do dia a dia.

---

## 🏗️ 2. Arquitetura do Módulo

O sistema está estruturado em três camadas independentes:

### 1. Camada de Dados (`src/types/codeBlank.ts` & `src/lib/data/codeBlanks.ts`)
* Cada desafio define:
  - `codeTemplate`: Código com tags demarcadoras (ex: `numeros.{{BLANK_1}}((n) => n * 2)`).
  - `blanks`: Array de lacunas com `id`, `placeholder`, `acceptedAnswers` (múltiplas variações válidas), `options` e `hint`.
  - `expectedOutput`: O resultado esperado retornado pela execução da função completa.
  - `explanation`: Feedback explicativo detalhado sobre a mecânica de software daquele exercício.

### 2. Motor de Reconstrução & Execução em Tempo Real
Em `CodeBlanksWorkspace.tsx`, a validação ocorre em três etapas encadeadas:
1. **Verificação de Preenchimento**: Garante que nenhuma lacuna ficou vazia.
2. **Validação Sintática**: Compara as respostas com `acceptedAnswers` de forma insensível a maiúsculas/minúsculas e espaços.
3. **Execução Segura em Sandbox**: O template é montado com as strings do usuário e avaliado via `Function` assíncrona isolada:
   ```javascript
   const runner = new Function(`return (async function() {\n${finalCode}\n})();`);
   const result = await runner();
   ```
4. **Comparação de Saída**: O retorno da execução é comparado com `expectedOutput`.

### 3. Feedback Multissensorial & Gamificação
* **Áudio Procedural**: Acordes harmônicos de vitória via Web Audio API (`sfx.playSuccessChime()`) e tons de alerta em caso de erro (`sfx.playErrorTone()`).
* **Confetes Neon**: Disparo de física de partículas no Canvas.
* **Streak Counter**: Contador de acertos consecutivos (`🔥 X seguidos!`) persistido por sessão.
* **Recompensa de XP**: Atribuição de experiência ao usuário com persistência em `localStorage` e perfil.

# 🏆 Sistema de Conquistas & Gamificação (Achievements)

> [!abstract] Visão Geral do Sistema
> O módulo de Conquistas do **DevQuest** recompensa marcos técnicos e de consistência do desenvolvedor com medalhas colecionáveis e bônus de XP. O sistema é persistido no [[02.1 - Neon PostgreSQL & Drizzle ORM|Neon PostgreSQL]] via Drizzle ORM e conta com fallback em memória resiliente.

---

## 🗄️ 1. Modelos de Dados (Drizzle ORM)

Em `src/lib/db/schema.ts`, foram introduzidas duas tabelas relacionais com integridade referencial e deleção em cascata:

```typescript
export const achievements = pgTable("achievements", {
  id: text("id").primaryKey(),
  slug: text("slug").notNull().unique(),
  title: text("title").notNull(),
  description: text("description").notNull(),
  icon: text("icon").notNull(),
  category: text("category").notNull(), // desafios, streak, projetos, seguranca, ranking
  xpReward: integer("xp_reward").default(100).notNull(),
  createdAt: timestamp("created_at").defaultNow().notNull(),
});

export const userAchievements = pgTable("user_achievements", {
  id: uuid("id").defaultRandom().primaryKey(),
  userId: uuid("user_id").references(() => users.id, { onDelete: "cascade" }),
  achievementId: text("achievement_id").references(() => achievements.id, { onDelete: "cascade" }),
  unlockedAt: timestamp("unlocked_at").defaultNow().notNull(),
});
```

## ⚡ 3. API Route (`/api/achievements`)

A rota `src/app/api/achievements/route.ts` expõe a lista de conquistas disponíveis e verifica se o usuário autenticado já as desbloqueou:

* **Endpoint**: `GET /api/achievements`
* **Autenticação**: Opcional. Se autenticado, preenche a flag `unlocked: true` e a data `unlockedAt`.
* **Resiliência**: Caso o banco de dados Neon esteja inacessível ou sem migração, a rota responde com a lista estática de conquistas mockadas (`mockAchievements`), impedindo travamento na UI do aluno.

---

## 🌱 4. Automação de Seed

O script `src/lib/db/seed.ts` foi atualizado para popular automaticamente as conquistas no Neon Serverless Postgres via:
```bash
npm run db:seed
```
Utilizando `onConflictDoNothing()` pelo campo `id`, garantindo idempotência em execuções repetidas.

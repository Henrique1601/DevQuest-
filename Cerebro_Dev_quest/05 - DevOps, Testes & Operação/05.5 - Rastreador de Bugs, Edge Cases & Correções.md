# 🐞 Rastreador de Bugs, Edge Cases & Correções

> [!abstract] Catálogo de Qualidade & Resiliência
> Este documento registra os principais bugs, comportamentos inesperados e edge cases identificados durante a evolução do DevQuest, acompanhados de suas causas-raiz e soluções arquiteturais aplicadas.

---

## 🔍 1. Áudio & Web Audio API

### 🐛 Bug: Autoplay Policy Bloqueando Efeitos Sonoros
* **Sintoma**: `DOMException: The AudioContext was not allowed to start. It must be resumed (or created) after a user gesture on the page.` no console do navegador.
* **Causa**: Navegadores baseados em Chromium e Safari bloqueiam a inicialização automática de contextos de áudio antes do primeiro clique do usuário.
* **Correção**: Implementado em `src/lib/audio/sfx.ts` um padrão singleton preguiçoso (*lazy initialization*):
  ```typescript
  if (!this.ctx) {
    const AudioCtx = window.AudioContext || (window as unknown as { webkitAudioContext: typeof AudioContext }).webkitAudioContext;
    this.ctx = new AudioCtx();
  }
  if (this.ctx.state === "suspended") {
    await this.ctx.resume();
  }
  ```

## 🖥️ 2. CodeMirror & Next.js SSR

### 🐛 Bug: Erro de Hidratação ao Carregar CodeEditor
* **Sintoma**: Inconsistências visuais ou erro `document is not defined` durante a renderização no servidor (SSR) do Next.js App Router.
* **Causa**: O CodeMirror 6 acessa diretamente nós do DOM e propriedades de medição de fontes que só existem no browser.
* **Correção**: Carregamento dinâmico com flag `ssr: false` e renderização de um componente `Skeleton` como fallback:
  ```typescript
  const CodeEditor = dynamic(() => import("@/components/challenges/CodeEditor"), {
    ssr: false,
    loading: () => <Skeleton className="h-full w-full" />,
  });
  ```

## 🪟 3. Ergonomia de Janelas & Split Pane

### 🐛 Edge Case: Colapso de Painéis ao Arrastar Divisória
* **Sintoma**: Ao arrastar o divisor do Split Pane para os extremos da tela, o editor ou a área de testes ficavam com largura zero, tornando impossível reverter o arrasto.
* **Causa**: Ausência de limitadores (*clamps*) matemáticos nas coordenadas do mouse.
* **Correção**: Limitador percentual estrito entre 25% e 65% da largura da janela em `ChallengeWorkspace.tsx`:
  ```typescript
  const newPercent = (e.clientX / window.innerWidth) * 100;
  if (newPercent >= 25 && newPercent <= 65) {
    setSplitPercent(newPercent);
  }
  ```

## 💾 4. Armazenamento Local & Auto-save

### 🐛 Edge Case: Thrashing de I/O no `localStorage` durante Digitação Rápida
* **Sintoma**: Queda de frames por segundo (jank) e múltiplos disparos de serialização ao digitar rapidamente no editor de código.
* **Causa**: Atualização síncrona do `localStorage.setItem` a cada `onChange` de caractere.
* **Correção**: Hook customizado `useCodeDraft` com timer de debounce de 800ms:
  ```typescript
  const timeoutId = setTimeout(() => {
    localStorage.setItem(storageKey, code);
    setIsSaving(false);
  }, 800);
  return () => clearTimeout(timeoutId);
  ```

---

## 🌐 5. Resiliência da API de Conquistas & Neon Postgres

### 🐛 Edge Case: Timeout ou Indisponibilidade de Rede do Banco de Dados
* **Sintoma**: Falha completa na renderização da tela de perfil ou conquistas caso o banco Neon esteja em escala zero inicial (*cold start*) ou a variável `DATABASE_URL` não esteja presente.
* **Causa**: `db.select()` lançando exceção não tratada.
* **Correção**: Em `src/app/api/achievements/route.ts`, implementado bloco `try/catch` com fallback elegante: se a conexão com o Neon falhar, a rota retorna os `mockAchievements` com status 200 e flag `resilientFallback: true`, garantindo zero quebra na interface do usuário.

## ⌨️ 6. Command Palette & Event Listeners

### 🐛 Bug: Acúmulo de Listeners Globais no `window`
* **Sintoma**: O atalho `Ctrl+K` disparava múltiplas vezes após várias navegações entre rotas.
* **Causa**: Falta da função de cleanup no hook `useEffect`.
* **Correção**: Registro seguro com remoção estrita:
  ```typescript
  useEffect(() => {
    const handleKeyDown = (e: KeyboardEvent) => { ... };
    window.addEventListener("keydown", handleKeyDown);
    return () => window.removeEventListener("keydown", handleKeyDown);
  }, []);
  ```

## 🎭 7. Testes E2E (Playwright) & Responsividade Mobile

### 🐛 Bug: Timeout em Seletores de Texto Ambíguos em Telas Desktop
* **Sintoma**: Teste E2E `Arena de Desafios - DevQuest › deve alternar entre abas de Instruções e Dicas` sofrendo timeout de 30s ao executar `page.click("button:has-text('Dicas')")`.
* **Causa**: Foi adicionado um componente mobile tab switcher (`lg:hidden`) contendo um botão *"Enunciado & Dicas"*. Em resoluções desktop (viewport padrão do Playwright 1280x720), essa barra mobile estava oculta no DOM com `display: none`. O seletor `has-text('Dicas')` resolveu para múltiplos elementos e tentou interagir com o primeiro (o elemento mobile oculto), causando timeout esperando que o elemento ficasse visível.
* **Correção**: Renomeada a aba mobile para *"Enunciado"* (removendo a ambiguidade com *"Dicas"* da barra principal) e garantido isolamento semântico entre a interface mobile e desktop:
  ```tsx
  // Antes: causava colisão de seletores de texto no Playwright
  <button>Enunciado & Dicas</button>
  // Depois: conciso para mobile e sem colisão de texto
  <button>Enunciado</button>
  ```

## ⚙️ 8. Web Worker Code Runner & Validação de Assinatura de Função

### 🐛 Bug: `SyntaxError: missing ) after argument list` ao errar o nome da função
* **Sintoma**: Ao submeter uma função com nome diferente do esperado pelo desafio (por exemplo, `inverterString` em vez de `reverseString`), a saída exibia o erro enigmático de sintaxe do V8: `missing ) after argument list`, em vez de acusar que a função esperada não havia sido definida.
* **Causa**: No arquivo `src/hooks/useCodeRunner.ts`, dentro da fábrica do Web Worker (`createWorkerScript`), a linha que construía a exceção continha escape incorreto de aspas:
  ```javascript
  // Antes: gerava string corrompida com aspas coladas e palavras soltas
  "  throw new Error('A função \\'' + challenge.functionName + '\\' não foi definida.');\\n"
  ```
  Ao ser avaliado pelo `new Function` no worker, o JavaScript interpretava as palavras `não foi definida` como identificadores avulsos fora de qualquer string literal dentro da chamada de `Error(...)`, disparando o erro de sintaxe `missing ) after argument list`.
* **Correção**: Corrigido o encapsulamento de aspas duplas escapadas de forma limpa:
  ```javascript
  // Depois: gera 'throw new Error(\"A função \\\"\" + challenge.functionName + \"\\\" não foi definida.\");'
  "  throw new Error('A função \\\"" + challenge.functionName + "\\\" não foi definida.');\\n"
  ```
  Agora, caso o aluno erre o nome da função, o sistema exibe com clareza:
  `A função "reverseString" não foi definida.`

## 📐 9. Layout & Z-Index: Sobreposição de Navbar Fixa

### 🐛 Bug: Conteúdo da Página de Code Review Oculto sob a Navbar
* **Sintoma**: Ao acessar a página `/code-review`, o topo da interface (header de diffs, botões de análise e métricas) ficava parcialmente escondido por baixo da barra de navegação global.
* **Causa**: A `Navbar` principal possui posicionamento `fixed top-0` com altura de 80px (`h-20`). O componente de página `/code-review/page.tsx` renderizava o `<CodeReviewWorkspace />` diretamente sem margem ou padding superior compensatório.
* **Correção**: Envolvido o workspace em container flexível com `pt-20 min-h-screen bg-background`:
  ```tsx
  export default function CodeReviewPage() {
    return (
      <div className="pt-20 min-h-screen bg-background">
        <CodeReviewWorkspace />
      </div>
    );
  }
  ```

## 🔄 10. Web Worker Console & Referências Circulares

### 🐛 Edge Case: `TypeError: Converting circular structure to JSON` ao usar `console.log(obj)`
* **Sintoma**: Se o código do usuário no editor logasse um objeto complexo do DOM, nó de árvore ou estrutura com referência circular (`obj.self = obj`), o Web Worker travava silenciosamente ou quebrava a serialização de mensagens enviadas via `postMessage`.
* **Causa**: Chamada direta de `JSON.stringify()` sem tratamento de exceção ao interceptar `console.log`, `console.warn` e `console.error` dentro do worker.
* **Correção**: Implementado serializador defensivo `formatArg` em `src/hooks/useCodeRunner.ts`:
  ```javascript
  function formatArg(a) {
    if (typeof a === 'object' && a !== null) {
      try {
        return JSON.stringify(a, null, 2);
      } catch (err) {
        return String(a);
      }
    }
    return String(a);
  }
  ```
  Isso garante que referências circulares recaiam graciosamente para `[object Object]` sem abortar a execução dos testes nem congelar a interface.

## 🚪 11. CSS Stacking Context, `backdrop-filter` & Portals

### 🐛 Bug: AppSidebar renderizada por baixo do editor hero da página inicial
* **Sintoma**: Ao abrir o menu "Labs & Mais", o cabeçalho da sidebar aparecia, mas o corpo ficava obscurecido e elementos com CSS `transform` (como o `.hero-editor` animado por GSAP na Home) renderizavam por cima da gaveta lateral.
* **Causa**: Pela especificação W3C, a propriedade `backdrop-blur-xl` no elemento `<header>` cria um novo Bloco de Contenção (*containing block*) e Contexto de Empilhamento (*stacking context*). O `position: fixed` e `z-[100]` da `AppSidebar` ficavam confinados dentro do `<header>` (que tinha `z-50`). Como a tag `<main>` vinha após `<header>` na árvore DOM, os elementos com `transform` em `<main>` sobrepunham o conteúdo da sidebar.
* **Correção**: Implementado `createPortal(..., document.body)` com `z-[9999]` e verificação de montagem no cliente (`mounted`) em `src/components/layout/AppSidebar.tsx` e `src/components/layout/CommandPalette.tsx`. O DOM é teleportado para a raiz absoluta do `<body>`, ficando livre de qualquer restrição de container ancestral.

## ⚡ 12. Estado Obsoleto & Falsa Conclusão ao Navegar na Arena

### 🐛 Bug: Avançar para o próximo desafio marcava como concluído e disparava confetes
* **Sintoma**: Após resolver com sucesso um desafio na Arena, ao clicar na seta `>` para avançar para o próximo desafio não resolvido, o sistema imediatamente tocava os acordes de vitória, disparava confetes neon e marcava o novo desafio como "Resolvido".
* **Causa**: O hook `useCodeRunner` mantinha os `results` do desafio anterior em memória. O componente `ChallengeWorkspace` possuía um `useEffect` com dependência em `[results, error, currentChallenge.id]`. Quando o usuário trocava de desafio, `currentChallenge.id` mudava, disparando o efeito enquanto `results` ainda continha os testes aprovados da questão anterior!
* **Correção**:
  1. Implementada a função `resetRunnerState()` em `src/hooks/useCodeRunner.ts` (esvaziando `results: []`, `consoleLogs: []`, `error: null`).
  2. Adicionado efeito em `ChallengeWorkspace.tsx` que invoca `resetRunnerState()` a cada mudança de `currentChallenge.id`.
  3. Adicionada referência de controle `lastExecutedChallengeRef`: os confetes e o salvamento em `solvedChallenges` só disparam se `lastExecutedChallengeRef.current === currentChallenge.id`, e a referência é imediatamente consumida (`null`).

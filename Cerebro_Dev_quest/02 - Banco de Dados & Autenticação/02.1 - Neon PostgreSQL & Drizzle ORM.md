# 🗄️ Neon PostgreSQL & Drizzle ORM

> [!abstract] Camada de Persistência Serverless
> O DevQuest utiliza o **Neon Serverless PostgreSQL** como banco de dados em produção e o **Drizzle ORM** como motor de mapeamento objeto-relacional com type-safety estrito.

---

## ⚡ Por que Neon Serverless?

1. **Auto-suspend & Scale-to-Zero**: Reduz custos para zero em períodos de inatividade sem perda de dados.
2. **Conexões HTTP/WebSocket Serverless**: O pacote `@neondatabase/serverless` contorna a limitação clássica de pool de conexões das funções Serverless da Vercel através de pooling via proxy HTTP.
3. **Database Branching**: Permite criar ramificações de banco instantâneas para testar migrações perigosas sem afetar a branch `main`.

---

## 🔌 Inicialização da Conexão (`src/lib/db/index.ts`)

```typescript
import { neon } from "@neondatabase/serverless";
import { drizzle } from "drizzle-orm/neon-http";
import * as schema from "./schema";

const sql = neon(process.env.DATABASE_URL!);
export const db = drizzle(sql, { schema });
```

---

## 🛠️ Comandos de Migração & Seeds

O gerenciamento de schema é feito através do `drizzle-kit`:

* `npm run db:push`: Aplica alterações de schema diretamente no banco Neon sem necessidade de arquivos intermediários lentos.
* `npm run db:seed`: Executa o script `src/lib/db/seed.ts` para popular trilhas, desafios e projetos iniciais com dados reais.
